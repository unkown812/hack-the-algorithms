# Algorithm Trace Format

## Overview

The DAA Learning Companion uses a structured execution trace format to represent algorithm execution step by step. Traces are generated by algorithm-specific TypeScript functions and consumed by the visualization webview.

## ExecutionStep

Each step in an algorithm's execution:

```typescript
interface ExecutionStep {
  id: number;
  description: string;
  operation: string;
  lineNumber?: number;
  currentState: VisualizationState;
  highlightedElements?: number[];
  comparedElements?: number[];
  swappedElements?: number[];
  updatedElements?: number[];
  variables?: Record<string, unknown>;
  explanation: string;
  complexity: ComplexityCounters;
}
```

### Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | number | Sequential step number |
| `description` | string | Short description of the operation |
| `operation` | string | Operation type (e.g. `compare`, `swap`, `init`, `found`, `divide`, `merge`, `partition`) |
| `lineNumber` | number | Corresponding pseudocode line number (1-based) |
| `currentState` | VisualizationState | Complete state after this step |
| `highlightedElements` | number[] | Array indices highlighted as current focus |
| `comparedElements` | number[] | Array indices being compared |
| `swappedElements` | number[] | Array indices being swapped |
| `updatedElements` | number[] | Array indices whose values changed |
| `variables` | Record<string, unknown> | Algorithm variables (e.g. `i`, `j`, `low`, `high`, `mid`) |
| `explanation` | string | Human-readable explanation for beginners |
| `complexity` | ComplexityCounters | Cumulative operation counts at this step |

## ComplexityCounters

```typescript
interface ComplexityCounters {
  operations: number;
  comparisons: number;
  swaps: number;
  iterations: number;
}
```

Counters reflect actual algorithm operations, not animation frames.

## VisualizationState

```typescript
interface VisualizationState {
  array?: ArrayState;
  graph?: GraphState;
  matrix?: MatrixState;
  tree?: TreeState;
  variables: Record<string, unknown>;
  stepIndex: number;
  status: AlgorithmStatus;
}
```

### ArrayState

```typescript
interface ArrayState {
  values: number[];
  length: number;
  elementStyles: Record<number, VisualStyle>;
}
```

### VisualStyle

```typescript
interface VisualStyle {
  state: VisualStateType;
  color?: string;
  label?: string;
}

type VisualStateType =
  | 'default' | 'active' | 'comparing' | 'selected'
  | 'swapping' | 'updated' | 'sorted' | 'found' | 'eliminated';
```

## AlgorithmTrace

Complete execution record:

```typescript
interface AlgorithmTrace {
  algorithmId: string;
  algorithmName: string;
  category: string;
  input: unknown;
  steps: ExecutionStep[];
  initialState: VisualizationState;
  finalState: VisualizationState;
  totalOperations: number;
  totalComparisons: number;
  totalSwaps: number;
  status: 'completed' | 'failed';
}
```

## Constraints

- No arbitrary code execution: traces are generated by pure TypeScript functions.
- Deterministic: same input always produces the same trace.
- Offline: no external API calls required for trace generation.
- Independently testable: each generator can be unit-tested without the webview.
